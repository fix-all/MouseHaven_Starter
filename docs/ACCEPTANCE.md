## B. 性能：先记录事实，再判断预算

测试对象是 Release 产物，不是 IDE 内的 Debug 进程。记录 Windows 版本、CPU、逻辑处理器数、显卡、分辨率、缩放比例、SDK/运行时版本、部署方式和采样区间。

建议每个活跃场景采样 60 秒，静止场景另观察 5 分钟。这些是测试采样时长，不是开发耗时预估。

| 场景 | 要记录的项目 | 状态 |
| --- | --- | --- |
| 微型静止 | CPU、绘制调用次数、内存、后台定时器活动 | 未测试 |
| 微型行走/干活 | CPU、帧率、内存、可见流畅度 | 未测试 |
| 展开横版 | CPU、内存、帧率、系统合成开销变化 | 未测试 |
| 外出演示 | CPU、各窗口绘制次数、交接是否抖动 | 未测试 |
| 暂停/隐藏 | 绘制是否停止、CPU 是否回落、是否仍有帧循环 | 未测试 |
| 反复切换后 | 与相同初始状态比较内存、GDI 资源和线程数，是否持续增长 | 未测试 |

首轮建议预算（未测目标，不是承诺）：移动时最高 30 FPS；微型静止时没有持续重绘；微型活动期间的进程 CPU 平均占整机逻辑计算能力争取低于 1%；默认模式工作集先争取在 80 MiB 以内。工作集、私有字节、私有工作集要分列，不能混用名字。后续参考实测再收紧，不用删除核心交互换取漂亮指标。

进程 CPU 整机归一化口径：

```text
100 × 采样间隔内进程累计 CPU 秒数 / 采样墙钟秒数 / 逻辑处理器数量
```

此计算只是统一报告口径，不保证与每个系统监控工具的显示完全一致。还要记录系统桌面合成器或 GPU 开销变化，不能只看自身 CPU。

## C. 核心自动化测试

- Home → Desktop → Home 全程只有一个角色所有权。
- 切换 Micro / Expanded 不更改行为进度和世界状态。
- 返回中重复触发 Startled 不复制任务或重置至无限回程。
- 返回目标随家园锚点改变而更新。
- 暂停与恢复不会重复结算动作或生成额外角色。
- 非法/损坏配置恢复为可见的默认位置，不导致无法启动。
