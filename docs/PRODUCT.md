# 产品规格：两套表现，三档大小

## 1. 产品目标

一个轻量 Windows 桌面娱乐产品：鼠鼠在有小屋、菜地、花园的家园里自行生活，偶尔跑到桌面上做无损捣蛋演出。默认存在感极小；用户点击家园才展开观察。不要求用户投喂或经营。

用户已明确的要求：默认只有聊天发送按钮量级大小，局部跟随鼠鼠；展开仍为马里奥式横版 2D，16:9，不要太大；最大化才切换为 2.5D 家园；鼠鼠外出不会把家园撑大；点击桌面鼠鼠后她逃回家；最终倾向啃咬不常用的文件或文件夹；资源消耗必须低。

本规格下面的数值、实现路线与阶段划分是建议，尚不是用户确认的最终参数。

## 2. 显示状态

| 状态 | 初始试验尺寸 | 表现 | 镜头 |
| --- | --- | --- | --- |
| Micro | 40×40 逻辑像素；同时可试 32/48/64 | 横版 2D，紧凑透明遮罩 | 跟随鼠鼠，仅显示很小局部 |
| Expanded | 内容区 480×270 逻辑像素 | 同一个横版 2D，16:9 | 增加可见范围，保留清晰角色尺寸 |
| Maximized | 显示器工作区，后续实现 | 2.5D 斜视家园 | 展示布局和生活细节 |

逻辑像素不是固定物理像素。须处理缩放比例与坐标换算，验证 100%、150%、200%；Windows DPI 模式参考 [S4]。

默认遮罩类似小观察口或柔边舞台，不压暗整个桌面，不做实时灯光。微型家园屏幕位置可以由用户调整并保存，但不会自行追着鼠鼠横穿桌面。

展开不是把一个模糊小位图暴力拉伸。要从场景重新绘制适合当前窗口的可见区域。首轮可以保持角色清晰度，同时增加可见范围。

## 3. 鼠鼠与窗口不是同一个对象

视图模式：Micro / Expanded / Maximized。
角色所在区域：Home / Desktop。
行为状态：Idle / Walk / Work / ExitHome / Roam / Nibble / Startled / ReturnHome / Hide。

三者分别存储。不把“微型且外出”“展开且外出”等组合写成大量复制的世界。

鼠鼠从家园出口跨出时，角色显示权从家园画面交接给桌面角色窗口；必须连续，不能同时画两只。外出时家园显示入口附近的空景，尺寸保持原档位。点击家园展开，也不会在里面再生成鼠鼠。

回家目标是当前家园入口在屏幕上的位置。测试期间用户移动、展开或收起家园时，应重新计算入口，不能仍跑向旧坐标。

## 4. 交互

点击微型家园：展开。点击展开窗口的收起按钮：回到微型。

点击外出鼠鼠：受惊，立刻中止捣蛋并返回；逃跑中再次点击不反复重置路径。

默认微型家园与桌面角色不抢当前应用焦点；不要强制激活。Windows 原生不激活窗口能力见 [S3]。主动打开管理窗口或后续最大化时可以采用正常窗口焦点行为。

完全透明的区域必须不挡底下的鼠标操作；家园可见观察口和鼠鼠本体应可点击。不要给整个可交互窗口加全局穿透标记，使角色本身也点不到。原生分层窗口命中规则见 [S2]。

提供托盘的暂停、恢复、显示家园、重置位置、退出。默认静音，不拦截键盘，不抢鼠标。

## 5. 2.5D 的安排

最大化的 2.5D 是正式需求，不取消；但不放进 P0 首轮。

下一轮优先用简陋素材验证斜视二维投影：能看到屋顶与侧面，物体按位置遮挡，不要求实时三维、自由转镜头或动态光照。

两个视角共享场所 ID、移动路段及进度、作物状态、动作阶段。横版和 2.5D 分别呈现同一位置与动作。不要假定只放大侧面图片就能得到 2.5D；需要不同视角素材及位置映射。

P0 的实现保留这些数据边界，但不构建完整三维、复杂导航或通用引擎。

## 6. 真实桌面与啃咬

P0 只对程序自己显示的虚拟文件夹做演出，不读取真实桌面目录、不识别使用频率。

后续把真实桌面图标对齐作为单独技术验证。最终只在用户允许的范围内读取最低必要元数据，不读取文件内容，不扫描整盘，不上传路径或日志。

“不常用”是近似偏好，不宣称精确知道用户使用习惯。具体可用信号、权限、排除机制需另做调查；无法可靠判断时随机选择或不执行，不虚构闲置天数。

碎屑及咬痕只画在自己的表面，退出后自然消失，用户文件和图标数据始终不变。

## 7. 暂不做

账户、联网、聊天、实时 AI、自动启动安装、商业分发、付费、完整农场经济、多宠物、复杂室内、真实文件写入、自动判断用户视线、持续截图或摄像头。

先验证交互和常驻负担，再验证美术吸引力与付费意愿。
