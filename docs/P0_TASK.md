# P0：可运行的横版桌面交互原型

## 1. 本轮交付的体验

启动后出现发送按钮量级的小观察口；鼠鼠在里面行走和干活。点击家园，展开为 16:9 横版近景；收起后回到原位置、原尺寸。通过托盘的“演示外出”，让鼠鼠从家园出口走到桌面的虚拟文件夹旁；点击她，她受惊跑回入口并隐藏。全过程只有一只鼠鼠。

这是交互原型，不是可发布成品。桌面外出首轮由开发者主动触发；正式随机外出和全面的桌面可见性判断后续实现。

## 2. 首轮建议技术路线

基线为 Windows 桌面，优先在 Windows 11 x64 测试。不要凭 User-Agent 猜测开发者系统，先检查实际环境。

采用 C# + .NET 10 正式稳定版；其 LTS 状态参考 [S0]。检查已安装 SDK，锁定实际验证过的正式版本，记录依赖。不要在文档中虚构已经安装的补丁号。

建议项目：

```text
src/MouseHaven.Core/          # 纯状态、时钟、路径与动作逻辑
src/MouseHaven.Windows/       # 消息循环、窗口、绘制、托盘、配置
tests/MouseHaven.Core.Tests/  # 核心状态测试
assets/                      # 原创占位素材与元数据
docs/                        # 规格、验证结果
```

Windows 层可使用 WinForms 消息循环、NativeWindow、NotifyIcon，再封装必要 Win32 互操作。不要引入网页运行时、网络后端或完整游戏引擎。

本路线是首轮取舍，不承诺一定比其他框架省资源。保留绘制接口；若后续大窗口绘制成为瓶颈，用测量决定是否更换后端。

### 窗口与绘制

- 家园使用符合当前可见大小的窗口；桌面鼠鼠使用紧包角色的小窗口。虚拟文件夹只在演示期间存在。
- 建议使用每像素透明的分层窗口和缓存的预乘 Alpha 位图，正确释放 DC、位图及窗口资源。不要每帧重新加载图片。
- `UpdateLayeredWindow` 会更新整个窗口；微软建议窗口尽量小，因此禁止默认创建全屏透明绘制表面。[S1]
- 使用正确透明命中和不激活行为，不能把整个鼠鼠窗口设置成不可点击。[S2][S3]
- 在创建窗口前确定 DPI 模式，统一保存逻辑尺寸和物理屏幕坐标的换算；参考 PerMonitorV2。[S4]
- P0 先完成单显示器；不满足的多显示器情形需明确记录。位置恢复失败时回到主显示器工作区，不让入口永久丢失。

### 状态和时间

只有一个 WorldState 和一个行为调度器。所有视图读取同一快照，不拥有独立宠物。

世界状态不存窗口句柄；视图切换不重置动作计时器。桌面坐标与家园坐标分开。把场所 ID、移动路段与路段进度作为稳定数据，方便下一轮给 2.5D 增加不同位置映射。

动作决策低频或按事件调度；画面有变化时才启动最高 30 帧的渲染。动画关键帧可以更少，位移按经过时间推进。静止时停止重绘，隐藏/暂停时取消帧定时器。不要用忙循环、持续 1ms 计时或每帧落盘。

暂停后恢复不能高速补播积压帧。使用单调时钟计算动作时间；采用明确的暂停策略。P0 不实现离线收益或长时间补算农场。

### 本地数据

只保存窗口位置、尺寸偏好、允许范围内的少量应用状态。存到应用自己的本地目录；采用临时文件和替换策略，损坏时恢复默认并给出可理解的错误信息。不得改动桌面原文件。

## 3. 必须实现

### P0-A：微型与展开

1. 微型默认 40×40 逻辑像素，可通过托盘对比 32/48/64；所有尺寸都是测试值。
2. 展开内容区默认 480×270，16:9。展开与收起保留家园锚点，不超出当前显示器工作区。
3. 横版家园至少包含入口、一块菜地、一朵花。镜头在家园内跟随鼠鼠，不移动整个家园窗口。
4. 鼠鼠至少有站立、行走、干活三个可辨动作；可用简单原创占位图，但必须有能辨认的耳朵、身体和尾巴，不能仅用圆点代替。首轮不要求最终美术。
5. 透明区不挡点击，微型家园不会自动抢焦点。右键/托盘可退出。

### P0-B：外出和返回

1. 托盘“演示外出”启动一次可重复测试。初始只从微型、在家且非忙碌转场状态触发。
2. 测试者先显示桌面再启动。P0 不宣称已能可靠识别所有全屏/桌面覆盖场景；给出演示模式标识和随时暂停入口。
3. 鼠鼠先走到入口，再移交给桌面角色窗口，走向程序自绘的虚拟文件夹。
4. 家园保持微型。点击家园仍可展开；外出的鼠鼠不会因此回到家园画面里。
5. 点击桌面鼠鼠后中断啃咬，受惊返回当前家园入口，进入 Hide，短暂停顿后恢复家园生活。
6. 鼠鼠外出时移动或调整家园，回程入口应更新；重复点击不产生新实例或多条并行回程。
7. 桌面角色不自动放大成另一个尺度。跨出观察口时保持视觉尺寸连续。
8. 演示结束或程序退出时，虚拟文件夹与碎屑全部清理。

### P0-C：可测试与可退出

1. 托盘具备暂停、恢复、显示/收起家园、尺寸试验、重置位置、演示外出、退出。
2. 加入可开关诊断记录：当前模式、角色归属、动作、绘制次数、进程 CPU 时间与内存。不要把诊断文字塞进微型观察口。
3. 用固定随机种子和可替换时钟做单元测试；测试切换模式不复制角色、不重置行为。
4. 退出释放所有窗口、托盘资源和定时器，进程真正结束。

## 4. 明确不做

P0 不实现最大化 2.5D，不展示会把横版拉满冒充 2.5D 的“最大化”按钮。下一轮先做 2.5D 占位视图与连续性测试。

不访问真实桌面文件；不做使用频率排名；不做复杂生长系统、聊天、云端、账号、付费、上架或自动开机启动。

## 5. 必须交付

完整源码；可替换的占位素材；README 中准确的构建/运行/发布命令；实际测试记录；能运行的 Release 产物（仅在环境能够成功构建发布时交付）；`docs/P0_REPORT.md`；按 `ACCEPTANCE.md` 逐项记录通过、失败和未测试。

报告区分：静态代码检查、自动化核心测试、Windows UI 测试、性能测量。没有 Windows 图形环境时，明确标记 UI 与性能未验证，不伪造结果。

完成 P0 后停止扩展。先依据实际运行效果和占用确定下一轮，不自动开始 P1。
